# Supabase

The orchestrator and dashboard run against the **Maintainer** Supabase project.

## Project

| Field | Value |
| --- | --- |
| Project ref | `gpnsaswidreusgkyemvi` |
| URL | `https://gpnsaswidreusgkyemvi.supabase.co` |
| Region | `eu-west-1` |
| Postgres | 17.6 |

The publishable (anon) key is safe to ship to browsers and lives in the dashboard env. The secret (service role) key is for server-side workflows only and never gets committed.

## Layout (planned)

```
supabase/
├── config.toml         # Generated by `supabase init` once we start migrations
├── migrations/         # Numbered .sql files, one per schema change
└── seed.sql            # Local dev seed
```

## Local setup

Once we start authoring schema:

```bash
brew install supabase/tap/supabase   # macOS
supabase login
supabase link --project-ref gpnsaswidreusgkyemvi
supabase db pull                     # fetch current schema as a migration
```

Migrations are applied to the cloud project with `supabase db push` after review.

## Type generation

Generated TypeScript types will live in `packages/supabase/types.ts`:

```bash
supabase gen types typescript --project-id gpnsaswidreusgkyemvi > packages/supabase/types.ts
```

Re-run after every migration. Both the orchestrator and dashboard import from `@maintainer/supabase`.
